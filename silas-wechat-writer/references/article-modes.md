# 题材与扩展模式

只在对应任务需要时使用；这些是组织材料的方向，不是强制套用的模板。

## 题材方向

- 源码阅读：具体卡点 → 调用主线 → 2–4 个关键节点 → 文件/函数证据 → 下一步阅读路径。避免把模块列表当文章。
- 工具实验：想完成什么 → 实际操作 → 结果 → 卡点和边界 → 适合的用途。没有执行过就不能写成实测。
- 项目复盘：为什么做 → 后端/前端接入链路 → 验证 → 容易遗漏之处 → 工程经验。
- 审计方法：漏洞模式或误判 → 排除弱问题 → 攻击路径 → 资产影响 → 证据与验证。材料未证实的风险不能升格为实际漏洞。
- Polymarket 篮球研究：规则 → 市场与数据 → 流动性和仓位 → 候选过滤 → 为什么跳过。遵守用户当前资金约束和已核验事实，不把记忆中的本金当成现值。
- 安全故事：异常 → 排查 → 信任或逻辑错误 → 可能业务影响 → 分层修复 → 验收。明确技术事实与虚构场景的区别。

## 热点选题

用户明确要求找热点且没有确定题目时，先搜索近 7 天新闻/原帖，记录时间，筛选能落到用户工具使用、源码、项目经验或审计判断的题目。给选题池、推荐主题和理由，等用户选题后再写正文。用户已经选题或授权代选时直接继续，不增加确认。选题材料放工作目录，用户要求单独保存时再作为交付。

## 外部写法参考

用户要求看 X 或其他平台怎么写时，先核对技术事实源，再看原帖/长文和可见传播数据。区分已读原文与搜索摘要，提炼开头、读者、技术解释顺序与承诺边界，不搬夸张观点。正文只列支撑技术判断的来源，标题研究过程另放笔记。

## PPT、视频及多平台

只有用户请求时增加对应产物。公众号文章仍是完整正文；PPT 每页围绕一个判断或结构图；录制提纲服务口头讲解，不把文章逐段粘成幻灯片。可用时使用对应专业技能。附加交付放同一内容目录，命名清楚，避免未经要求同时产出多种格式。
