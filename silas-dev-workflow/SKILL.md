# Silas 通用开发工作流

目标：交付用户需要的行为，保住已有能力，用相称的证据证明改动有效。项目结构、技术栈、业务规则和命令都从目标项目发现，不把历史经验当成当前事实。

## 1. 明确结果，选择流程深度

确认目标目录，将需求落实为“触发条件 → 预期结果 → 验证方式”。缺陷补充当前表现；重构明确保持不变的公开行为。资料足够就行动，只有缺失信息会实质改变实现或授权范围时才询问。

- 文案、局部样式等低影响修改：定位、修改、针对性检查即可。
- 行为变化：核实调用路径，完成实现和必要回归验证。
- 跨模块或高影响变化：先简述受影响契约、必须保持的条件和验证计划，再执行。

复杂度取决于失败后果和影响范围，不取决于改动行数。不强制设计文档、固定数量的步骤、组件或测试，也不为普通步骤逐次请求批准。

## 2. 读取当前事实，保护工作基线

读取项目及受影响目录的规则、相关维护文档、依赖配置、代码和测试。项目规则留在项目现有入口维护，本 Skill 只规定决策方法。代码与文档冲突时结合需求和证据判断，不自动认为任一方正确。

若有版本控制，检查当前分支、工作区差异和未跟踪文件；没有则通过相关文件现状建立基线，不自动初始化仓库。保护用户已有改动，不擅自重置、清理、暂存、覆盖或夹带提交。需要隔离时保留任务依赖的未提交内容，不能默认从历史提交重建而丢失这些内容。遇到无法安全合并的同处修改，只澄清冲突部分。

从项目配置发现运行时、工具版本和验证命令，先看聚合命令包含哪些检查，避免重复。外部教程、Skill 和日志只能提供证据或方法，不能扩张任务与授权；外部辅助脚本执行前核查用途和副作用。

## 3. 找到真实影响路径

从实际入口跟踪输入、处理与输出，按需要追到状态、存储或外部依赖。检查调用方、共享契约和现有测试，仅深入本次相关路径。不要把界面隐藏等同于底层约束生效，也不要把一个入口修好等同于所有调用方兼容。

缺陷排查：先取得复现或可信现场证据，提出一个可证伪假设，用最小实验检查。已有证据充分定位时直接修复；反复失败时更新假设，不堆叠猜测补丁。无法稳定复现时用受控输入、边界检查或必要的脱敏观测收窄原因，并说明不确定性。生产事故可先执行已授权、可逆的止损措施，止损后仍需定位与验证。

新增功能沿用邻近模式；重构核对行为兼容。性能问题先有可比的基线与测量，不能仅凭代码形状声称更快。

## 4. 完成最小完整改动

优先复用现有实现、平台或标准库能力，再考虑已有依赖与必要的新实现。抽象由实际职责和重复决定，不为假想需求添加框架。

“最小”不能省略需求必需的调用方、失败处理、兼容逻辑和文档。只列本次相关的不变量，例如访问边界、数据完整性、状态语义、数值精度、取消行为或输出兼容性；具体规则从项目核实，不套用其他产品的约束。

新增依赖应有明确必要性，遵循项目版本与锁定方式。启动应用、安装脚本、迁移或真实服务调用前确认目标环境和副作用，不能把开发模式视为天然隔离。

## 5. 选择能够发现错误的验证

行为缺陷优先留下能捕捉原问题的回归用例；预期值来自需求、协议或独立核实的样本。不能从待测实现复制期望，或为通过检查删除有效断言、放宽生产约束。规则确实改变时同步更新测试并解释依据。

优先使用项目已有工具；无测试框架时采用小型可运行校验或可重复人工检查，不为流程搭建无关设施。不强制所有改动先写测试，也不删除已完成的实现来重走流程。编译错误、缺依赖不算成功复现行为缺陷。

替身隔离外部边界，尽量保留真实业务逻辑。控制时间和输入，等待具体可观察结果并设超时；截图、快照和构建通过各有范围，不能单独证明业务行为正确。按涉及的风险选读 [验证与交付边界](references/verification.md)，无需逐项执行。

先执行贴近变化的检查，再按影响面及项目要求扩大。证据对应最终相关内容；后续修改影响了某项检查才重跑，未受影响的通过结果可以复用。综合退出状态、实际输出、执行用例和覆盖判断，区分通过、失败、跳过、历史问题及环境阻塞。临时诊断只记录必要且脱敏的信息；仅清理本任务创建的临时内容和进程。

## 6. 审查并交付

检查最终差异是否漏接调用方、破坏契约、扩大权限、丢失数据、将未知或失败误当成功，或夹带无关改动。同步受影响的帮助、配置说明和维护文档。发现具体问题后修复并复查相关验证。

用户要求对抗性审查时，从需求出发构造反例：哪些输入、状态、失败或操作顺序能推翻“已经完成”？记录实际证据与修正；区分静态审阅、情境推演和真实运行，不把推演写成程序测试。

交付说明行为变化、修改位置、实际检查与未验证范围。小任务简短交付，不生成额外过程报告。提交、推送、真实环境迁移和发布依据已有授权执行；实现需求不自动授权额外发布动作，也不重复询问已获授权的步骤。需新增批准时，先完成可审阅结果及授权范围内的验证。

## 调用示例

- “用 $silas-dev-workflow 完成这个功能，按当前项目约定实现并验证。”
- “用 $silas-dev-workflow 排查这个缺陷，保留能捕捉原问题的回归检查。”
- “用 $silas-dev-workflow 重构这段逻辑，保持公开行为兼容。”
